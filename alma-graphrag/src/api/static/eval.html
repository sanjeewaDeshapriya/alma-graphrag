Step 1 — The query set & gold standard

Evaluation replays a fixed set of natural-language traveller questions against the same city hotel pool for every system, so any difference in scores reflects the retrieval method only. Each query ships with a gold standard: the set of hotels that should be returned. Gold is rule-based and graded (0 / 1 / 2): a hotel is fully relevant (2) when it satisfies every constraint strictly, partially relevant (1) inside a tolerance band (price +15%, rating −0.2, star −1, travel +2 min) — so no baseline's hard cut-offs act as a perfect oracle. Human relevance labels supersede it per-query when gold_human.json is present.

Step 2 — The five systems being compared

All five retrieve from the identical candidate pool and return a ranked top-K list of hotel ids. They differ only in what evidence they can see.

Filter baseline

Traditional filter-and-sort — the real-world OTA behaviour. Applies the structured constraints parsed from the query, then ranks survivors by rating (cheaper first on ties).

Keyword baseline

Lexical retrieval — Postgres full-text search (tsvector / ts_rank) over hotel name, description and amenity text. Matches exact word forms only: “quiet” does not match “peaceful”.

Semantic baseline

Dense-vector retrieval — sentence-transformers embeddings (all-MiniLM-L6-v2, 384-d) indexed in pgvector, ranked by cosine similarity. Generalises over wording, capturing meaning rather than exact terms.

Step 3 — How each ranked list is scored

Evaluated at K = 10, per query, then averaged. Precision / Recall / MRR use binary relevance (grade ≥ 1); nDCG uses the graded gains (2 = fully, 1 = partially relevant), so ranking a fully-relevant hotel above a borderline one scores higher. Differences vs GraphRAG are significance-tested (paired bootstrap + Wilcoxon).

Precision@10

P@10 = (relevant hotels in top-10) / 10

Of what we showed, how much was right. Rewards a clean top-10.

Recall@10

R@10 = (relevant in top-10) / (all relevant)

Of everything relevant, how much we surfaced. Rewards coverage.

nDCG@10 graded

DCG = Σ gaini / log2(i + 1) · nDCG = DCG / ideal-DCG · gain ∈ {0, 1, 2}

Rank-sensitive with graded gains: a fully-relevant hotel at rank 1 is worth more than a borderline one. The headline metric.

MRR

MRR = 1 / (rank of first relevant hotel)

How quickly the first good answer appears. 1.0 means rank 1.

Step 6 — Evaluated against real human choices

Steps 1–5 grade against evaluation/gold.py — rules we wrote. This step grades against what 247 participants actually booked in the discrete-choice study. It answers a different question: not “does the ranking satisfy the stated constraints?” but “does it predict what people choose?”

Why both evaluations are reported. The rule-based gold is nearly blind to ranking: hard filtering prunes on the same predicates the gold grades on, so 45 of 60 queries score identically across every weight configuration. The choice data separates them clearly — but it cannot measure price sensitivity (participants spent no real money) and covers only ten scenarios. Neither replaces the other.
